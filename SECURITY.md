# Security notes — AutoSyndicate v5

## Что уже защищено

Клиент больше не получает право произвольно менять чужие строки через открытые RLS-политики. Все write-операции онлайн-модулей требуют Supabase Anonymous Auth. `player_profiles`, рынок, чат, банк и PvP используют ownership-поля на базе `auth.uid()` и серверные `BEFORE`-триггеры для критичных переходов состояния.

На стороне браузера дополнительно введены ограничения размера save/import, нормализация состояния, whitelist ID машин, числовые диапазоны, очистка пользовательского текста, лимиты цены/ставок, chat rate limit и Content Security Policy.

## Что нельзя считать полностью защищённым

Экономика основной игры всё ещё хранится в `localStorage`, а результат одиночной гонки рассчитывается клиентом. Пользователь, который сознательно меняет JavaScript/DevTools, технически может изменить собственный локальный баланс, характеристики или заявленный результат PvP. RLS не может доказать, что физика гонки действительно была пройдена честно.

Для production-экономики с реальной ценностью нужен следующий архитектурный шаг: сервер-авторитетный кошелёк и инвентарь, RPC/Edge Functions для покупок/ставок/наград, idempotency keys, серверный журнал транзакций и проверяемая сервером модель результата. До этого SYND следует считать игровой виртуальной валютой без денежной ценности.

## Ключи

`SUPABASE_KEY` в `js/multiplayer.js` — publishable key. Его допустимо публиковать при корректном RLS. **Никогда** не вставляй в клиент `service_role`, database password, JWT signing secret или другие серверные секреты.

## Telegram

Telegram `initDataUnsafe` удобно использовать для UI, но для серверной идентификации нельзя доверять ему без проверки подписи `initData` на backend. Если позже появятся реальные платежи, призы или ценные активы, проверка Telegram initData должна выполняться только на сервере.
