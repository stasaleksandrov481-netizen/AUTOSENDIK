# Security notes — AutoSyndicate Expansion v8

## Что усилено

Онлайн-записи используют Supabase Anonymous Auth, ownership через `auth.uid()`, RLS и серверные guard-триггеры. Клиент не получает `service_role` и не должен его получать.

Рынок теперь хранит полный `vehicle_data`. Сервер ограничивает размер JSON, совпадение `carId`, уровни тюнинга и диапазоны топлива/состояния. Поля мощности, build score и стоимости тюнинга в UI пересчитываются из базовой машины и уровней деталей, поэтому продавец не может просто подменить эти цифры в JSON и заставить интерфейс показать их как достоверные.

Реферальная система хранит связь inviter/invitee и начисления на сервере. Самореферал запрещён, referrer неизменяем, начисления записываются в уникальный ledger, прямые изменения referral-таблиц клиентом запрещены.

Save v8 хранит резервные копии и нормализует состояние. Для кейсов награда и списание фиксируются до завершения визуальной рулетки. Для собственных активных рыночных лотов выполняется reconciliation с сервером после авторизации.

## Важное архитектурное ограничение

Основной кошелёк SYND и большая часть одиночной экономики всё ещё являются клиентским состоянием (`localStorage`). Результат одиночной гонки также рассчитывается браузером. Пользователь с DevTools может модифицировать собственный клиент и попытаться отправлять завышенный `total_earned`; сервер ограничивает отдельный прирост профиля, но это не является полноценной доказуемой античит-системой.

Если SYND когда-либо получает реальную денежную ценность, нужен сервер-авторитетный контур:

- wallet ledger в БД;
- серверные RPC/Edge Functions для наград, покупок, кейсов, рынка и ставок;
- idempotency key на каждую экономическую операцию;
- инвентарь машин/деталей/номеров в БД с уникальными instance ID;
- серверная валидация результатов гонки или подписанные race sessions;
- rate limits и аудит подозрительных приростов.

До такой миграции SYND следует считать виртуальной игровой валютой без денежной ценности.

## Ключи

В клиент разрешён только Supabase publishable/anon key. Никогда не помещай в `index.html` или JS:

- `service_role`;
- пароль PostgreSQL;
- JWT signing secret;
- секреты платёжных систем;
- Telegram bot token.

## Telegram

`initDataUnsafe` подходит для отображения имени/аватара, но не для доверенной идентификации платежей или ценных активов. Для этого подпись Telegram `initData` должна проверяться на сервере.
